# Задание 01 — развёртывание закрытого стенда на VPS

Репозиторий basilsolanji-hash/Messenger-KnitERP, продукт «Ось коммуникации». Основу брать от актуального `main`, SHA записать в отчёт. Цепочка PR #1–#8 уже в `main`; старые ветки и задания `2026-10-23-*` не продолжать.
Цель — закрытый тест текстовой переписки двух физических телефонов. Целевая дата 26 октября 2026 года, но готовность по одной дате не заявлять.

## Принятые решения (docs/DECISIONS.md, 25 октября)

- VPS и домен у пользователя есть. Доступы (SSH, DNS, сертификат) передаются вне чата и git. Секреты не коммитить и не выводить в логи.
- SMS: Fake-провайдер; код выдаёт оператор через `/api/v1/dev/*` вне APK. Платные SMS.ru не включать.
- Доступ: только список IP тестировщиков и отдельный список операторов, всем остальным отказ. Мобильный интернет со сменой IP не поддерживается; VPN — только отдельным решением пользователя.
- Телефоны: два физических, один на Android 8, второй на актуальном Android.

## Область работы

`deploy/`, серверные `scripts/`, `server/` (только исправления, найденные при развёртывании), `docs/CLOSED_HTTPS.md`, `deploy/README.md` и отчёт `docs/reviews/2026-10-25-closed-stand.md`. Android, языки, `mobile/` и основную ERP не менять. Production guard не снимать: API остаётся Development за закрытым HTTPS.

## Шаги

1. Если у исполнителя нет SSH-доступа (облачная сессия), подготовить точный пошаговый runbook с командами для пользователя, а результаты собрать с его слов и выводов. Выполненным считать только то, что подтверждено выводом команды.
2. До изменений на VPS: инвентаризация уже работающих сервисов, занятых портов (особенно 443), firewall, версий Docker Compose v2, Nginx, Python 3.10+, age. Чужие сайты не останавливать.
3. Checkout в `/opt/os-communications` по `deploy/README.md`. `.env` создать только через `scripts/init-dev.py`; права 0600. `AllowedHosts` — реальный домен. `Dev__EnableOperatorEndpoints=true` и сильный `Dev__ProvisioningKey` — только для операторского Fake-сценария.
4. TLS: сертификат публичной CA с DNS SAN, отдельный резервный ключ для второго pin. `scripts/prepare-closed-https.py` с реальными `--tester`/`--operator` IP. Проверить `nginx -t` от сервисного пользователя.
5. `Auth__TrustedProxies__0` — фактический peer IP Nginx, видимый API, а не подсеть. Отрицательная проверка: поддельный `X-Forwarded-For` не обходит лимит 5 SMS за 10 минут.
6. Сначала systemd unit для Compose и `/health/ready` через loopback, затем выделенный HTTPS unit. Firewall снаружи: только 443 и SSH 22 по ключу. API 5080 и PostgreSQL извне недоступны — проверить снаружи.
7. Отрицательные проверки с внешнего адреса: IP вне списка получает отказ, операторские пути недоступны тестировщикам, неверный pin и HTTP отклоняются.
8. Ручной зашифрованный backup (`server-backup.py --quiesce-api`), проверка `verify` на отдельном компьютере с офлайн-ключом, восстановление в отдельный пустой PostgreSQL 18. Рабочие volume не трогать, `down -v` и prune запрещены. Timer включать только после успешного восстановления.
9. Передать пользователю и Android-исполнителю `server-endpoint.json` (`{origin, pins}`) — без токенов, паролей и операторского ключа.
10. Настроить и проверить отзыв сессий оператором и выключение операторских endpoint'ов после теста.
