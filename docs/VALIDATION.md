## Пределы результата

PGlite исполняет PostgreSQL в WebAssembly и мультиплексирует соединения. Успешные тесты подтверждают проверенные сценарии на этой среде, но не заменяют проверку блокировок и многопроцессной конкуренции на обычной PostgreSQL 18. Такая проверка предусмотрена в GitHub Actions и пока не выполнялась.

Docker-сборка и Compose не запускались в текущей среде, где Docker отсутствует. Dockerfile и инструкция подготовлены, их работоспособность требует фактического контейнерного запуска.

На момент первой серверной поставки libsignal и Android ещё не проверялись. Последующие результаты приведены ниже. Тест двух Android-телефонов, SMS-регистрация, Google Play и Beget пока не выполнены. Ранее созданный скрин-макет не является доказательством работоспособности приложения.

### Проверка ввода и выбора языка через Compose

В итоговой сборке на чистом эмуляторе Android 8 x86_64 прошли **3 инструментальных теста**, 76,01 с: `DemoInputTest`, `LanguageResourcesTest`, `EncryptedVaultTest`. Новый Compose-тест проверил поле ввода до отправки и отображение полного сообщения `knitERP_test_01 — Тест 0123456789` после отправки, автоматический локальный ответ и переключение Беларуская → Қазақша → O‘zbekcha → Русский через реальные элементы настройки языка. Запуск камеры, серверная доставка и физическая клавиатура телефона в эту проверку не входят.

Снимки главного экрана, чата и выбора языка получены через `captureToImage()` реального Compose-интерфейса и выгружены из cache тестового приложения. Это снимки работающей сборки, а не макеты. Логотип отображается целиком, без обрезки; цвет выбранной вкладки согласован с брендом.

Ранний сценарий с `adb shell input text` сохранил `knitERP_test_` вместо ожидаемого `knitERP_test_01`, поэтому полный сценарий не был засчитан. После перезапуска фактический текст и ответ остались в истории. В контролируемом Compose-тесте расхождение не повторилось; причина раннего результата не установлена, ввод обычной экранной клавиатурой на физическом телефоне ещё подлежит проверке.

Фактический вывод итогового набора: `test-results/2026-10-22/android-8-compose-and-storage.txt`. Успешный локальный прогон не является успешным GitHub Actions: клиентский workflow также завершился до шагов, без доступных логов.

## Сетевой прототип 0.2 — фактические проверки

- JVM: **17 тестов core и 9 тестов network** прошли без ошибок и пропусков. Проверены повтор отправки и claim после потери ответа, повтор при потерянном ACK, откат при сбое хранилища, отказ ACK повреждённому конверту, проверка принадлежности сессии, TLS pinning, системное доверие CA, запрет redirect, истечение сессии и ограничение размера ответа.
- Два HTTP-сценария (`:core:serverSmoke :network:serverSmoke`) прошли на настоящем ASP.NET API и PostgreSQL 18.6/PGlite. Новый сценарий использует тот же типизированный API и Delivery, что Android: офлайн inbox, повтор send, COMMIT до ACK, потеря ACK и новый экземпляр контроллера, ответ, совпадение safety numbers, `/me`, продление той же тестовой сессии и отказ при несовпадающем публичном ключе. Это JVM-клиенты, а не два Android-телефона.
- Сервер собран в Release без ошибок/предупреждений; 3 unit-теста авторизации прошли. `/me` и выдача сессии теперь сообщают точный срок из JWT с секундной точностью; проверка нашла и устранила расхождение дробных секунд.
- Android APK и APK инструментальных тестов собраны. В 0.2 добавлено INTERNET; системное доверие TLS, hostname и SPKI pins обязательны в публичной фабрике сетевого адаптера. HTTP разрешён только внутреннему конструктору JVM loopback-теста; Android UI его не использует.
- CLI проверен на синтаксис, справку и валидацию origin/pins. Полный вызов CLI через настроенный HTTPS-стенд ещё не выполнен.

Краткий результат: `test-results/2026-10-22/network-0.2-jvm.txt`. Это не отменяет перечисленных выше ограничений PGlite, отсутствия успешного CI, проверки двух телефонов и полноценной регистрации.
