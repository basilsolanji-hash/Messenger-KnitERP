# Состояние серверной и клиентской основы

Дата: 22 октября 2026 года.

## Реализованный код

- Серверный транспорт, тестовые аккаунты, PostgreSQL inbox/outbox, prekey claims, дедупликация, ACK, блокировка и отзыв устройства. SignalR передаёт только событие о доступной очереди.
- Kotlin-модуль с настоящим libsignal 0.105.4, ECC/PQ prekeys, проверкой подписей и identity, атомарным ratchet/outbox и ratchet/inbox, повтором после сбоя, 60-значным fingerprint и сравнением QR payload.
- Проверенный JVM-обмен через HTTP API и очередь PostgreSQL 18.6/PGlite: офлайн-адресат, повтор send, потеря ACK, расшифровка и ответ.
- Android Compose-код локального тестового чата: **два профиля на одном устройстве**, Room/SQLCipher, ключ базы под Android Keystore, в исходной поставке использовался логотип knitERP; текущая клиентская ветка переводит заголовок на текстовое название «Ось коммуникации». В версии 0.2 добавлен отдельный сетевой профиль с HTTPS/SPKI pinning, индивидуальной тестовой сессией и ручной синхронизацией постоянного outbox/inbox; INTERNET теперь запрашивается.
- Debug APK собраны отдельно для четырёх ABI. На эмуляторе Android 8 x86_64 в версии 0.2 прошли четыре инструментальных теста: полный ввод и отправка через Compose, переключение четырёх языков, Keystore/Room/SQLCipher, ресурсы, публичный запрос подключения и запрет HTTP-конфигурации; установка на физический ARM64-телефон пока не проверена.
- Интерфейс и выбор языка: русский, белорусский, казахский, узбекский (латиница). Исторические сообщения при смене языка не переводятся.
- Исправлена точность времён при первом принятии сообщения: первое подтверждение и повтор из PostgreSQL используют одинаковую микросекундную точность.

## Еще не реализовано

- Фактическая переписка двух физических Android-телефонов, доступный им закрытый HTTPS-стенд. Вход пока только операторский по 15-минутной сессии, не SMS. Сканер QR и поток подтверждения нового identity/устройства.
- Серверная часть SMS-входа, PIN, подписи device challenge и refresh rotation есть в ветке `claude/auth-v1` ([AUTH.md](AUTH.md)), но не подключена в Android и не проверена с реальным SMS.ru. Recovery code не реализован: закрытый отказ.
- Группы, Sender Keys, медиа, FCM и фоновые задачи Android.
- Полный профиль и приватность, контактный поиск, жалобы, удаление аккаунта и публикация.
- Настройка Beget, публичного домена и TLS, эксплуатационный backup и восстановление.
- Распределенный rate limiting для общего API. Лимиты SMS и refresh уже общие (PostgreSQL); общий limiter запросов по-прежнему действует в одном экземпляре процесса.
- Ротация подписанных prekeys. В этапе 0 подписанный ключ неизменен; повторная загрузка не возвращает одноразовые ключи в пул.

Этот код не является завершённым этапом 1 и не разрешает публичный запуск. Старые C#-тесты транспорта используют синтетические ключи; новый JVM-тест отдельно использует настоящие ключи libsignal. Пополнение одноразовых пулов ещё не реализовано.

## Границы проверок

Фактические результаты сборки, пройденные тесты и ограничения фиксируются в `VALIDATION.md`. Наличие workflow или теста не считается выполненной проверкой. Целевая дата и минимальный состав закрытого запуска находятся в `DELIVERY_TARGET.md`.

## Сетевой прототип 0.2

Инструкция и точные ограничения находятся в `CLOSED_TEST.md`. В очереди реализованы устойчивый повтор одного шифротекста, ACK после COMMIT, повтор после потерянного ACK и ограниченная ручная синхронизация. Операторский CLI выдаёт индивидуальную сессию по публичному запросу телефона, без административного ключа в APK. `/me` подтверждает ключи и устройство; продление тестовой сессии требует совпадения тех же ключей. Это всё ещё не завершённый этап 1.

## Название и внешнее API

По решению пользователя экосистема называется «Ось», приложение — «Ось коммуникации». Меняем только это приложение и его сервер; основная система подключается внешним адаптером. Технические идентификаторы и старые сообщения сохраняются.

В клиентской ветке обновлены текстовое название, app label и новые демо-тексты во всех четырёх языках. Ресурсы XML корректны, наборы из 56 ключей совпадают. Повторный `python3 scripts/check-device-proof.py` выполнил 33 проверки. Новая сборка Android и инструментальные тесты после ребрендинга не выполнялись.

`OS_INTEGRATION_V1.md` и `OS_INTEGRATION.openapi.yaml` описывают проект внешнего API: связь аккаунтов, явное согласие, tenant/scopes, аудитория и отзыв ссылок на бизнес-объекты. В YAML 9 операций; выполнены разбор YAML и структурная проверка ссылок/operationId/path parameters. Полный OpenAPI-валидатор и работа сервера по этим маршрутам не проверялись: endpoints и служебная авторизация ещё не реализованы.
