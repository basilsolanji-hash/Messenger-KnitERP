Прежние результаты CI не приравниваются к прогону точной головы.

## Найдено и исправлено

1. **Высокая серьёзность: потеря всех администраторов при конкурентном управлении.** `LockUser` выполнял `FOR UPDATE` вне общей транзакции; блокировка освобождалась до проверки и изменения. Два администратора могли одновременно отключить или понизить друг друга, оба запроса возвращали 204. Новые проверки на двух экземплярах API воспроизвели оба случая.
2. **Средняя серьёзность: изменение доступа без записи в журнал.** `RevokeOtherSessions` сохранял роль/учётные данные и отзыв сессий до отдельного сохранения аудита. Тест с отказом PostgreSQL-триггера на вставку `change-role` получил HTTP 500, но роль уже стала `admin`.

Изменения учётных записей теперь выполняются с блокировкой таблицы `admin_users` до конца транзакции. Блокировка общая для экземпляров API, порядок одинаков для входа, веб-изменений и консольного создания. Чтение списков остаётся доступным. Веб-запрос сначала проверяет доступ до блокировки, затем повторно проверяет свежие сессию и роль после ожидания. Первая проверка также сохраняет отзыв сессии при смене сети вне откатываемой транзакции.

Роль, состояние учётной записи, пароль/ключ TOTP, отзыв сессий и аудит фиксируются вместе. Команда `admin create` также не сохраняет пользователя без аудита. Неверный текущий пароль по-прежнему записывается в журнал; смена пароля сохраняет текущую сессию и отзывает остальные.
