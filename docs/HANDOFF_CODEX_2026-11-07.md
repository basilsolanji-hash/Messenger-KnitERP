## Что сделано в ветке

1. **Новое устройство собеседника.** Принимается только после явной сверки нового 60-значного кода. Удержанные сообщения перешифровываются для нового устройства под теми же id.
   - Код: `SignalClient.previewChange/acceptChange`, `Delivery.checkPeerChange/acceptPeerChange/forgetPeerChange`.
   - Тесты: JVM, `LiveTransferTest`, прогон двух эмуляторов.
2. **Прогон «два телефона»** (`.github/workflows/two-phones.yml`, `TwoPhoneStepTest`). Эмуляторы Android 8 и Android 16 одновременно, каждый со своим приложением, общий API за HTTPS с pinning. Сценарий:
   - регистрация обоих;
   - переписка в обе стороны;
   - force-stop;
   - повторный вход;
   - отказ принять новое устройство до проверки;
   - подтверждение;
   - сверка кодов.
3. **Удержание неустранимых отказов.** `DELIVERY_UNAVAILABLE`, `IDEMPOTENCY_CONFLICT` и `RECIPIENT_DEVICE_CHANGED` удерживаются и не ломают синхронизацию. Пакеты, которые не проходят проверку, после 3 попыток подтверждаются и отбрасываются. Пакеты нового устройства собеседника не отбрасываются никогда.
4. **Запросы на переписку.** Текст от незнакомых скрыт до принятия. Блокировка — сначала на сервере (`POST /api/v1/blocks`), с подтверждением в интерфейсе.
5. **Лимит новых собеседников:** 100 key claims на аккаунт в сутки, общий для всех экземпляров (`Transport:Limits:ClaimsPerDay`).
6. **Операторская панель стенда** `/api/v1/dev/panel`. Работает только с Fake SMS и операторским ключом:
