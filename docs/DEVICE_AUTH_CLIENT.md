# Ось коммуникации: подтверждение устройства и клиентская авторизация

Клиентский код объединяет PR #3 и сетевую основу Claude PR #4. Бренд — «Ось коммуникации», протокольные идентификаторы сохраняются.

## Реализованные компоненты

- DeviceProofPayload.java — строгие канонические activate/refresh байты; Kotlin DeviceProof использует тот же построитель.
- DeviceAuthKey — отдельный неэкспортируемый P-256 ключ Android Keystore, реализующий DeviceSigner. Приватный Signal identity для подписи не используется.
- AuthApi — pinned HTTPS, ограниченный ответ, машинные ошибки, отдельные анонимные auth-запросы без Authorization.
- Login — сохранённый до отправки requestId, SMS и PIN шаги, проверка сессии перед сохранением. Номер хранится в зашифрованном профиле, строковые представления DTO скрывают его и секреты.
- UserSession / VaultAuthStore — refresh в одном экземпляре, durable journal и бюджет идентичного повтора, атомарное сохранение до использования access. Access остаётся в памяти, refresh — в SQLCipher.
- PinnedApi — провайдер access с одним повтором после 401; старый операторский режим сохранён.
- Текстовый бренд в четырёх языках; проект внешнего API в OS_INTEGRATION_V1.md и OS_INTEGRATION.openapi.yaml. Основная система в эту работу не входит.

## Интеграция пользовательского входа, 23 октября 2026

Вход SMS/PIN связан с единственным application owner, журналом подготовки отдельного профиля, восстановлением сессии, /me → immutable bind → publish → readiness. Текстовый чат по UUID и ручная синхронизация используют тот же SQLCipher/Signal/UserSession/Delivery. Выход фиксируется до HTTP, старые история и outbox сохраняются. Четыре языка: 112 совпадающих ключей.

До автоматической очистки рабочей среды прошли 68 JVM-тестов (17 core, 51 network), 0 ошибок/пропусков, и чистая Gradle-сборка четырёх ABI APK и AndroidTest: BUILD SUCCESSFUL in 1m 56s, 79 задач (70 выполнены, 9 актуальны). Device-proof — 33 проверки. После очистки исходники восстановлены и сверены по записанным blob SHA проверенной версии; это не новый прогон после восстановления. Эмулятор API26 загрузился и началась установка APK, но итог instrumentation/скриншот не получен; успешной проверку не считаем.

Результат и ограничения: reviews/2026-10-23-android-entry.md и test-results/2026-10-23/android-entry.txt. Живой UI-вход через API, HTTPS/Beget и два физических телефона ещё не приняты. Внешний integration API — проект без runtime endpoints. Оценка полного ТЗ около 25%, не процент тестов и не готовность публикации.

Два независимых задания: tasks/2026-10-23-claude-01-android.md (приёмка Android), tasks/2026-10-23-claude-02-server.md (сервер/закрытый HTTPS/восстановление). Основная ERP не входит в область работы.
